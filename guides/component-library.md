# Homely Component Library

Use existing components before creating new ones. A shared component must
document its purpose, API, states, responsive behavior, and accessibility
expectations.

Keep one-off sections local. Promote a section only when the Manager confirms
that it is reused or benefits multiple pages. The CEO approves changes to the
visual language or shared component contract.

## Review checklist

- Matches the approved design system.
- Covers loading, empty, error, hover, focus, and disabled states.
- Works at mobile and desktop widths without clipping.
- Has clear keyboard and screen-reader behavior.
- Uses a small, composable API.
- Has the relevant checks recorded.

The Manager returns this checklist with every UI review. No publication is
allowed until the Manager recommends approval and Hermes/CEO approves it.
